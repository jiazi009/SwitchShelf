# Backend allowlisted reader and durable journal worker

Read AGENTS.md, Docs/ARCHITECTURE.md and Docs/DEVELOPMENT_PLAN.md first. This is a hardware-free foundation task; the user authorized coordinator delegation but workers must not launch agents.

Ownership: only Sources/SwitchShelfBackend/FileAccess/**, Sources/SwitchShelfBackend/Journal/**, Tests/SwitchShelfBackendTests/FileAccess*.swift, Tests/SwitchShelfBackendTests/Journal*.swift, and Docs/Reports/backend-storage.md. Do not change Package.swift, BackendContracts.swift, Protocol, USB, Preflight, App or shared domain models. Other workers implement those scopes in parallel. Ask the coordinator before changing a shared contract. Use the existing BackendFileReading, BackendFileOffer, BackendTransferResult and BackendError contracts.

Implement an explicit allowlisted BackendFileReading actor from authoritative ID -> URL bindings and expected sizes. IDs are opaque and must never be parsed into paths. Read only requested bounded ranges, never hash or copy a whole source. Validate regular file, no symlink, safe range arithmetic, stable local identity/size/modification evidence before and after reads, short reads and cancellation. Opening and file work must not run on MainActor. Fail closed on missing/stale bindings, source replacement or symlink traversal. Document limits of Foundation/POSIX metadata and SMB blocking I/O; do not claim an enforceable hard deadline for blocked kernel filesystem calls. No production UI invokes the reader this wave; no real NAS source reads.

Implement an atomic local Codable journal for per-attempt/per-file host transfer state. Distinguish unrequested, partial, full coverage awaiting device confirmation, interrupted and failed/unknown outcomes; none means installed. Validate journal consistency and bound decoded data. On process restart active attempts become interrupted/unknown; never automatically resume/retry or promote installation state. Preserve an unknown/corrupt schema without overwriting it and report the recovery requirement. Atomic file replacement is required; document the precise crash durability guarantee. Avoid persisting unnecessary source paths, device identifiers or secret data. Use a local test path rather than the real user Application Support directory. A journal should not silently discard partial state on failures. Protocol worker may later supply progress callbacks; design public progress-recording APIs that can be integrated without changing contracts.

Hard boundary: no physical USB discovery/open/handshake/I/O, device writes, install attempt, real NAS reads, dependency installation, settings changes, other clients or current live app interaction. Validate only with tiny temporary fixtures and fake results. Tests named BackendFileAccess and BackendJournal should cover exact slices, opaque IDs, unknown/missing/stale sources, symlink/replacement/size changes, out-of-bounds/overflow, cancellation and short read semantics where deterministic; journal round-trip, atomic replacement, invalid transitions, restart interruption, concurrent updates and unknown/corrupt preservation. Run swift test --filter 'BackendFileAccess|BackendJournal' and build in your isolated worktree. Commit only owned paths on your branch, and report files, commands, test results, commit, limitations and no-hardware evidence via injected Orca lifecycle. Read coordinator mail at checkpoints and before worker_done.
