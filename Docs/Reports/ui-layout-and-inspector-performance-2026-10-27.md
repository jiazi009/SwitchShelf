# 分栏显示和详情打开性能优化 — 2026-10-27

## 目标与边界

用户报告顶部/侧栏被裁切，以及点击游戏打开右侧详情时卡帧。本轮以原生 SwiftUI/AppKit 布局、主线程工作和渲染粒度为优化范围；保留原生可调整详情侧栏、键盘多选、来源访问校验和保守安装状态，不改安装或 MTP 协议。

## 显示异常：复现与修复

此前回归只检查 NSWindow 尺寸，没有检查其内部视图是否真正落在窗口内，因此漏掉了“不崩溃但显示裁切”。新增真实 WindowGroup 的标题/品牌几何采样后，1516×809 窗口中复现：NSSplitView 仍有 1059 点高度，标题全局 y = -47，品牌 y = -3。空库的理想高度阻止原生分栏收缩，外层窗口本身尺寸正确并不能证明内容可见。

在 `LibraryView` 和 `SidebarView` 的根布局显式设定 `minHeight: 0, maxHeight: .infinity`，允许原生分栏接受视口高度，不靠裁剪掩盖溢出。修复后同尺寸标题 y = 52、品牌 y = 85。测试还检查 1276×1410、960×640、1280×820 的标题/品牌完全位于窗口高度内。上一轮空库不挂载 inspector 的崩溃保护继续保留。

## 主线程和渲染优化

- `AppModel.handleGridTap`：普通点击不再重新过滤、排序全库；只有 Shift 范围选择需要可见顺序。可注入修饰键用于确定性测试，UI 默认仍取实际事件。最近添加筛选只计算一次 ID 集合，避免逐游戏重建。
- `InspectorView`：详情及本地内容改为 LazyVStack；滚动到相关位置才创建文件行。内容按类型分组一次；单项安装判断直接使用所属 Game，不再为每行搜索整个游戏库。沿用同一 InstallationAssessor，不缓存或提升安装证据。
- `GameViews` / `CoverPalette`：JPEG 解码、最长边 480 像素的下采样和颜色采样在后台准备，MainActor 仅创建基于已解码 CGImage 的 NSImage 并提交视图。异步任务取消后不回写旧图片。
- 已解码封面缓存计入像素和 JPEG 成本，保持 64 MiB NSCache 预算。对于本地封面，仍先校验来源元数据/读取合法派生缩略图，只有缩略图字节未变才复用已解码图片；不以 URL 内存命中掩盖来源替换、损坏或符号链接。
- 选择动画仅作用于选中描边，不再把封面尺寸变化一起纳入选择动画；移除 hover 的重复全局动画事务。RootView 尊重“减少动态效果”偏好，正常情况下不关闭原生侧栏动画。

## 测量结果（不是 FPS）

用同一隔离、未显式启用优化的 SwiftUI 夹具，1000 个合成游戏、12000 项合成内容，连续普通选择 80 次：

| 同步选择路径 | 耗时 |
|---|---:|
| 诊断夹具恢复旧版无条件过滤/排序语句 | 34.741 ms |
| 优化路径，浅色重复运行 | 0.194–0.199 ms |
| 优化路径，深色重复运行 | 0.189–0.192 ms |

`--selection-baseline` 仅在临时编译副本中恢复该语句，并非整份旧版 App 的端到端对照。这些数字不包含 SwiftUI 后续布局、GPU 合成或磁盘/网络延迟，不能换算为详情动画 FPS，也不证明所有机器均无卡帧。真实逐帧性能仍需 Instruments / 显示刷新率条件下的专项采样；系统“减少动态效果”开关未做人工切换验收。
