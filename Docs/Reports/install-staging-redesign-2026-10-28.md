# 安装待选区交互改版 — 2026-10-28

## 确认的数据流与范围

- 继续使用 AppModel.plan / PlanItem / PlanContent 和现有 LocalPlanStore 保存待选任务；保留旧计划及明确的文件选择，不创建第二份可能失配的队列。
- 游戏卡片主体选择后将游戏累加到 plan，重复添加为幂等操作；右侧固定安装栏展示同一 plan，可移除及排序。匹配几何动画仅移动派生封面视图，不移动/复制游戏文件。
- 详情图标仅写入独立 detailGameID，以系统浮层展示单个游戏详情并提供关闭按钮；不改变 plan 或卡片选择，不再使用原生 inspector 挤压游戏库，也不在详情内提供安装操作。
- 新任务在 App 层选择本体、全部 DLC 和同一明确更新身份下唯一最高 rawVersion。无法比较的更新默认不选，显示明确选择/本次略过入口；不改共享领域模型或静默重写旧任务。
- 安装栏按钮自动调用现有 metadata-only checkPlan，再建立 SphairaBatchReview；保留已有全部文件/设备/目标授权确认。确认 sheet 上移 RootView，避免依赖队列页。继续调用 SphairaBatchInstaller 串行发送和原隔离 worker，保留释放、退出、取消、失败和未知结果保护，不改协议。
- 连接状态基于实际 USB 候选和忙状态给出指引；只读清单成功不等于 MTP Install 就绪。设备模式和实际目标仍需用户在 sphaira 确认，helper 在同一会话验证能力。
- 检查/复核期间锁定计划及自动 USB 读取，避免检查到确认之间被后台刷新或编辑打断。连接恢复不会自动发送，未知结果不自动重试。

本轮仅做软件/合成夹具与界面验收，不执行物理安装；保留已有用户数据和桌面工作树正式应用，不改 Package.swift、共享领域模型或全局设置。

## 实现文件

- `InstallationSidebar.swift`：320 点固定安装栏、空待选区、移除/上移/下移、文件复选、目标统一选择、常驻开始按钮、连接指引、真实串行进度与停止操作。历史传输结果与待选任务分开展示，不把“已发送”标成“已安装”。
- `GameInteraction.swift` / `GameViews.swift`：卡片和列表行使用独立的主体 Button 与详情 Button，保留键盘范围选择；匹配几何效果在源/目标之间切换，原卡片仍显示，不进行文件移动。遵守系统减少动态效果；另有测试用环境开关，无系统设置修改。
- `RootView.swift` / `InspectorView.swift`：固定待选栏代替原生 inspector；详情为独立系统 popover，带关闭按钮和 Escape。详情无安装动作。必要的文件/设备确认 sheet 由 RootView 呈现，与队列页解耦。
- `AppTypes.swift`：App 层默认本体、全部 DLC 和唯一同身份最高 rawVersion 更新；版本缺失、身份不一致、最高版本并列均不猜测。
- `AppModel.swift`：普通卡片点击累加 plan，重复点击保留既有内容/目标/顺序；模糊更新可明确选择或本次略过。开始按钮自动预检并建立复核，复核与准备期间锁定编辑和自动 USB 读取；双击不会创建并行执行。既有串行执行器与隔离安装 helper 未改。
- `LibraryView.swift` / `QueueView.swift` / `SwitchShelfApp.swift` / `MTPInstallConfirmation.swift`：游戏库显示待安装数量，列表与网格行为一致，菜单支持批量加入；原队列页保留高级顺序/文件编辑，开始流程不再依赖手动“检查计划”。
- `scripts/verify-install-staging.swift` 与已有 UI 夹具：逻辑、实际窗口鼠标事件、几何位置和 metadata-only 复核集成回归。未改 Package.swift 或 SwitchShelfDomain。

## 验收中发现并修正的问题

- 卡片上简单叠加详情 Button 会截断原有主体 TapGesture；真实事件测试发现卡片不再加入待选。改为两个独立原生 Button 后，详情与主体都通过网格/列表鼠标事件验证。
- 同时保留源和目标的 matchedGeometryEffect 会让缩略图追随源位置；改为仅在未待选源和已待选目标之间切换匹配，增加终点坐标/尺寸断言。
- 外部 Orca Computer Use 对新窗口返回 `permission_denied`，但只读权限查询显示 Accessibility/Screenshots 已授权。尝试恢复窗口和窗口列表后仍不可读取；未切换权限、重置 TCC、重启系统服务或以其他全局输入通道绕过权限。实际 App 的进程采样显示主线程正常等待事件，非挂起。交互验证采用上述隔离进程内部 AppKit 事件，系统窗口列表可确认实际测试版窗口可见；不声称取得了当前真实 App 的 AX 树或截图。

## 数据、安全与限制

- 用户原安装计划在本轮实际 App 重启前后为 0 项；代理没有在真实 App 中添加/删除任务。旧计划数据结构不变，已有明确选择不会被新默认规则覆盖。模糊更新的“本次略过”确认只作用于当前会话，再次添加或来源候选变化会重新要求选择。
