# Backend USB foundation (hardware-free)

Owned paths: `Sources/CDBIBackendUSB/include/CDBIBackendUSB.h`, `Sources/CDBIBackendUSB/bridge.c`, `Sources/SwitchShelfBackend/USB/BackendUSBTransport.swift`, `Tests/SwitchShelfBackendTests/BackendUSBTests.swift`.

The explicit `BackendUSBTransport.open(lease:)` is the sole Swift native-opening API; construction/import is inert. The caller **must provide** an MTP/Backend-shared `BackendUSBDeviceLease` implementing process/cross-process exclusivity. The coordinator must wire that lease into MTP before enabling this native path; currently no production UI/CLI opens it. The mandatory caller-supplied lease is the **only cross-process flock authority**; C retains a process-local gate but does not independently flock (which could conflict with a caller locking the same pathname). No implementation of the shared MTP lease is supplied here; do not infer integration is complete.

Native implementation uses SDK `IOUSBDevice` IOKit matching, `IOCreatePlugInInterfaceForService`, `IOUSBDeviceInterface` and `IOUSBInterfaceInterface`, `GetInterfaceClass`/`GetAlternateSetting`/`GetNumEndpoints`/`GetEndpointProperties` (interface 190, before open), and `GetPipeProperties` (after open), `USBInterfaceOpen` (never seize), `ReadPipeTO` and `WritePipeTO`, `USBInterfaceClose`. It rejects zero or multiple 057e:3000 devices, requires exactly one vendor-specific alternate-zero interface with exactly two bulk pipes 0x01 OUT and 0x81 IN. 057e:201d never matches. No serial reads, configuration changes, reset or device seize. Native reads/writes accept 1..1,048,576 bytes and 1..60,000 ms, and use finite IOKit no-data/completion timeouts; discovery, open and close do not have a forced deadline. A returned read count exceeding the original requested count is rejected; partial read is returned as-is; successful synchronous WritePipeTO is treated as complete by its API contract; failures are uncertain and never retried. Errors expose bounded `BackendError` classes, not device strings or numeric identity.

Swift actor fences concurrent I/O/close and holds process gate and caller lease across awaits; detached blocking IOKit calls are awaited to completion, including cancellation. Cancellation is checked before acquisition and native opening; cancelled open completes native work, closes a successful open exactly once, then releases both gates. An uncertain native open (`releaseUnverified`) is not blindly closed and retains the caller lease/process gate permanently. Cancelled read/write waits for native completion before reporting cancellation; close during I/O returns busy; double-close is unavailable. Close failure or caller lease release failure retains the process fence. C release failure also retains its process fence. The native pointer is private to an unchecked-sendable holder used serially under actor ownership; never pass it to app state.

Validation (no physical enumeration/open/handshake/read/write): `swift test --filter BackendUSB` — 2 passing tests (descriptor rejection, C invalid-handle paths, fake partial read/write/validation/busy/uncertain-open fence, cancellation before open and during delayed open/read/write). `swift build` — passed. `clang -fsyntax-only -Wall -Wextra -Werror -isysroot "$(xcrun --sdk macosx --show-sdk-path)" -I Sources/CDBIBackendUSB/include Sources/CDBIBackendUSB/bridge.c` — passed. No `/Volumes/switch 游戏包` access or official sender execution.

Limitations: IOKit's legacy `IOUSBDevice` service availability, device interface descriptor/class assumption, interface open feasibility without opening/configuring the device, actual pipe behavior and end-to-end timeouts have **no hardware proof**. IOKit synchronous `WritePipeTO` does not return a partial byte count; any non-success remains indeterminate. Open, descriptor inspection and close have no explicit finite deadline in this API (only I/O is bounded). A failed native open cleanup may not prove an externally claimed interface was released; production must stay disabled pending reviewed device validation. The earlier close-failure fake was replaced by an uncertain-open fence test because either failure intentionally poisons the process gate; close-failure handling remains implemented but lacks a separate isolated-process test. The task's prior test filename spec was `USB*.swift`; the existing `BackendUSBTests.swift` does not match that glob, but this follow-up explicitly authorizes that existing test file. Caller-provided lease implementation and MTP wiring belong to coordinator. No real device was contacted.
