# Backend USB foundation (hardware-free)

Owned paths: `Sources/CDBIBackendUSB/include/CDBIBackendUSB.h`, `Sources/CDBIBackendUSB/bridge.c`, `Sources/SwitchShelfBackend/USB/BackendUSBTransport.swift`, `Tests/SwitchShelfBackendTests/BackendUSBTests.swift`.

The explicit `BackendUSBTransport.open(lease:)` is the sole Swift native-opening API; construction/import is inert. The caller **must provide** an MTP/Backend-shared `BackendUSBDeviceLease` implementing process/cross-process exclusivity. The coordinator must wire that lease into MTP before enabling this native path; currently no production UI/CLI opens it. The C bridge additionally uses a nonblocking process lock and owner-checked, no-follow `/tmp/switchshelf-usb-session.lock` flock. This C lock alone cannot coordinate existing MTP transports; do not infer integration is complete.

Native implementation uses SDK `IOUSBDevice` IOKit matching, `IOCreatePlugInInterfaceForService`, `IOUSBDeviceInterface` and `IOUSBInterfaceInterface`, `GetInterfaceClass`/`GetAlternateSetting`/`GetNumEndpoints`/`GetEndpointProperties` (interface 190, before open), and `GetPipeProperties` (after open), `USBInterfaceOpen` (never seize), `ReadPipeTO` and `WritePipeTO`, `USBInterfaceClose`. It rejects zero or multiple 057e:3000 devices, requires exactly one vendor-specific alternate-zero interface with exactly two bulk pipes 0x01 OUT and 0x81 IN. 057e:201d never matches. No serial reads, configuration changes, reset or device seize. Native reads/writes accept 1..1,048,576 bytes and 1..60,000 ms, and use finite IOKit no-data/completion timeouts. Partial read is returned as-is; successful synchronous WritePipeTO is treated as complete by its API contract; failures are uncertain and never retried. Errors expose bounded `BackendError` classes, not device strings or numeric identity.

Swift actor fences concurrent I/O/close and holds process gate and caller lease across awaits; detached blocking IOKit calls are awaited to completion, including cancellation. Close during I/O returns busy; double-close is unavailable. Close failure or caller lease release failure retains the process fence. C release failure also retains its process fence. The native pointer is private to an unchecked-sendable holder used serially under actor ownership; never pass it to app state.

Validation (no physical enumeration/open/handshake/read/write): `swift test --filter BackendUSB` — 2 passing tests (descriptor rejection, C invalid-handle paths, fake partial read/write/validation/busy/release fence). `swift build` — passed. `clang -fsyntax-only -Wall -Wextra -Werror -isysroot "$(xcrun --sdk macosx --show-sdk-path)" -I Sources/CDBIBackendUSB/include Sources/CDBIBackendUSB/bridge.c` — passed. No `/Volumes/switch 游戏包` access or official sender execution.

Limitations: IOKit's legacy `IOUSBDevice` service availability, device interface descriptor/class assumption, interface open feasibility without opening/configuring the device, actual pipe behavior and end-to-end timeouts have **no hardware proof**. IOKit synchronous `WritePipeTO` does not return a partial byte count; any non-success remains indeterminate. Open and descriptor inspection have no explicit finite deadline in this API (only I/O is bounded). A failed native open cleanup may not prove an externally claimed interface was released; production must stay disabled pending reviewed device validation. Caller-provided lease implementation and MTP wiring belong to coordinator. No real device was contacted.
