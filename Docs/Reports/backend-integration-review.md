## Findings and evidence

- **Wire:** The pinned official [`dbibackend` at `22090afc64cc7b5d645a99bf3d4d8625a67b766e`](https://github.com/rashevskyv/dbi/blob/22090afc64cc7b5d645a99bf3d4d8625a67b766e/dbibackend) has DBI0/16-byte little-endian headers; request command EXIT=0, FILE_RANGE=2, LIST=3; newline-terminated UTF-8 list; FILE_RANGE header ACK before its size/offset/name payload, response header then ACK before file bytes. Protocol codec/session matches those *host-script* steps and validates headers, lengths, ACK type/command and offered name/range. The official script ignores response ACK fields; bounded ACK length is conservative but actual DBI 647 behavior remains unverified. There is no host-side SD/NAND command or installation-success evidence in EXIT.
- **Name/ID binding:** Preflight constructs offers from current uniquely matched `LocalContent` IDs and source URLs; plan IDs are never interpreted as paths. It checks the URL basename and current source size; session resolves requests by exact UTF-8 offered name to an opaque ID. Preflight accepts only supported package extensions and ≤255 UTF-8 bytes, narrower than codec's bounded general basename format. Follow-up root commits `b04a7ef` / local `92e47cd` reject empty IDs, align control/colon/newline names, compare exact UTF-8 bytes and remove opaque IDs from the UI. Storage commits `1470dbd` / local `6b8101d` and follow-up `5996d3a` / local `7aa7b5d` add and harden `AllowlistedBackendFileReader.open(bindings:)`, which binds each opaque ID to an explicit source URL/size and reads through bounded no-follow file-descriptor traversal with metadata checks; FIFO/NUL/bind cancellation are rejected. Source content is not hashed or independently verified.
- **Progress/ownership:** The `87174d1` follow-up closes exactly once after body success/failure, returns `releaseUnverified` on failed close, forbids reuse and emits per-file unique-coverage snapshots after successful host file-data writes. The total counts sent bytes including repeats; full host coverage remains `transferredAwaitingConfirmation`, not installed. The local journal persists each callback snapshot with monotonic per-file progress and marks active attempts interrupted on reopen; follow-up `5996d3a` validates coverage deltas, requires recorded EXIT before `.finished`, rejects multiple active attempts on reload and fences uncertain post-rename persistence. A successful write followed by crash before journal persistence is unknown. Backend USB explicit `open` is the only native-opening entry; current App queue's Start button is disabled and its action is empty, with no production Backend transport construction in the inspected App paths. Follow-up USB commits `3f88413` / local `9601f75` and `9d2463b` / local `19000a7` fence uncertain opens/acquires/releases, remove duplicate flock authority, bound native read lengths and add cancellation lifecycle fakes. USB caller lease still must coordinate with MTP before production transfer; no concrete MTP-shared production lease or native app call path exists.
- **Tests reviewed:** Protocol fake-peer cases exercise Unicode wire bytes, fragments, invalid headers/ACK, unknown and out-of-range names, overlap/partial coverage, callback failure, close failure and cancellation. Preflight tiny temp metadata tests cover missing/offline/nonregular/changed files, duplicate names and size/list limits. USB fake-driver tests cover descriptor predicate, validation, fragments, uncertain write and release fencing. These tests provide no actual hardware compatibility or installation proof.
